1. In your own words, what structure does HTTP add on top of the raw TCP byte stream used in Lab 2?
In lab2, raw TCP does not decide what are meaning of the bytes. and how to report error. 
However, for Http, it provides a standardized way of doing it.  e.g. GET(), POST(), DELETE()

2. What is the resource in this API? For POST /messages, GET /messages, GET
/messages?receiver=<name>, and DELETE /messages/<id>, explain what each method/path combination
does.
The resource is the messages. 
POST: create a new message in the JSON body

GET: reads the whole message collection and return every messages

DELETE: delete that particular message with that id


3. Name one common REST-related HTTP method that this message API does not use (for example PUT or
PATCH). How could the API be extended to use it meaningfully?
PUT would replace the entire existing resource
PATCH only does edite on the existing resource
if the API want to ammend a particular part of the message sent, it can use PATCH
if things are getting totally replaced, use PUT.

4. Why do many production APIs require an API key? What can the provider control or measure with it?
API key informs the provider which client is accessing the information.
It helps the provider to verify whether the client is eligible to access the requested information

5. Why should the client check the HTTP status code before assuming the response body has the successful
WeatherAPI JSON structure?
The error message informs the client whether the request was successful or not. If not, it tells why.
It also helps the client to verify that the reponse is a JSON body, so that no further local client error will be triggered
